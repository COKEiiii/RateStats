# 调研格式整理程序

这是独立的 Python 后处理步骤，可在采集、修正、生成完整调研表之后调用。核心模块仅使用 Python 3.11+ 标准库，不需要安装 openpyxl，也不要求安装 Excel。它不联网、不重新采集、不调用模型，不改变原采集流程或人工复核状态。

## 自己运行

双击项目根目录的 `整理调研表格式.command`，依次选择待整理的调研表、格式参考表和新文件保存位置。待整理表需要保留框架生成的采集明细。增幅使用输入表现有最新两列，不需要另选历史调研表。

原始文件和格式参考表不覆盖；输出路径已经存在时拒绝执行。输出旁边会生成 `.format-report.json` 处理报告，请检查其中的异常项目。

也可在项目目录指定已完成批次的全量调研表。将下方示例路径换成实际文件。

```sh
.venv/bin/python -X utf8 -m market_rates.report_format \
  --input "outputs/批次目录/日期_全量_调研.xlsx" \
  --template "templates/report-format.xlsx" \
  --output "outputs/example/report.xlsx"
```

输入应含当前期业务表和来源明细。下期换用对应批次的输入文件，输出选择新的路径。

只检查、不生成 Excel：

```sh
.venv/bin/python -X utf8 -m market_rates.report_format \
  --input "本期完整调研.xlsx" --template "格式参考.xlsx" \
  --dry-run --audit "本期格式检查.json"
```

比较固定使用各区块最左侧的最新日期列及其右侧相邻日期列，保留原日期和历史数据；不会查找其他采集文件，也不会插入一列。各区块相邻日期不同或两列同日时均保留原样。例如输入最新两列是 10 月 8 日和 10 月 1 日，就按这两列计算，不能从其他文件补出 10 月 7 日。新加入且没有历史数据的区块保留空白历史列，增幅为 `-`；有历史数字却缺少对应日期、或日期顺序异常时明确报错。旧 `--previous` / `previous_path` 参数已取消，传入时会提示改用原表两列。

缺少公式缓存时程序会停止。先在 Excel 中重算并另存原始完整调研，再重跑。已删除采集明细的成品不作为本程序的原始输入；自动化应保留整理前的完整采集报告作为下次比较底稿。

## 已实现规则

| 范围 | 规则 |
| --- | --- |
| SGD 主表、SGD 最高报价汇总 | 每银行、期限分组只保留一个 Personal 最高值；所有客群报价可供普通个人获得，计入 Personal。仅有 Premier/Preferred 时不回退冒充 Personal。 |
| 实际期限 | 8M 与 9M 分开，2M、4M、8M、10M 等模板缺少的分组动态增加，不用相邻月份代替。 |
| SGD 全部公开报价 | 保留利率、counter/online、金额门槛。同一银行、同一期限的公开报价中，只有出现两种或以上客群时才逐条标出 Personal/Premier/Preferred 等类别；全部为 Personal 时省略标签，即使有多个产品、金额档或渠道。Personal 与所有客群视为同一显示类别。重复报价去重，资格条件放简短备注。 |
| 普通促销与挂牌金额栏 | 只留金额、币种、等值币种及上下界。资格、渠道和必要说明移到备注。不同金额档位保留；存在历史数值冲突的金额行不强行合并。 |
| 数值 | 历史展示公式读取保存的结果后固定为值；独立的文字百分比转为数值。当日增幅和新版 Premier Rates 保留公式。新版 Premier 引用的“本期专属明细”保留，其他采集明细和外部工作簿链接移除。 |
| 最新两列比较 | 使用输入表现有最新日期列减去右侧相邻日期列，保留更早日期，不额外插入比较列。任一利率缺失时增幅显示 `-`，不跳到更老的非空值、不填零。 |
| 历史金额档位 | 使用完整调研生成阶段已经写入相邻日期列的数值，格式整理阶段不再跨文件匹配或补写历史报价。 |
| 增幅箭头 | 正数绿色向上，负数红色向下，零黄色水平。差额保留十位小数消除浮点尾差；显示仍按百分比。 |
| 日期 | 历史引用先固化，再更新当前汇总日期，避免修改汇总日期造成历史日期漂移。 |
| 样式 | 从参考表导入相应样式、列宽、页面设置，并按精简后的文字计算行高。历史表仅显示原表最新两列及增幅、备注；更早日期列保留并隐藏，冻结表头与标识列。不会复制把全部数据冻结、或把所有挂牌利率列隐藏的异常设置。 |
| 逐行可见性 | 解除遮住当前利率、上期利率、当日增幅、金额和备注的旧合并范围；保留银行名称等有效分组。保存后再次检查，不能只验证隐藏在合并单元格下的数值。 |
| 其他汇总区块 | 按实际表头识别金额和备注，按合资格 Personal 记录核对最高值及其金额，专属客群不参与。新增实际期限加入主表及汇总；旧日期列继续作为历史保留。 |
| Premier Rates | 利率按唯一记录编号引用“本期专属明细”J 列，格式对齐时不转为固定值；空白、零、记录缺失与重复分别处理。Minimum Amount 只保留存款金额；AUM、客户类别、新资金和渠道移入备注，避免把资产资格门槛当作起存金额。 |

版式检查还覆盖汇总页各币种区块、SGD 所有银行/期限、外币挂牌“其他要求”列、长备注和表头。行高按实际列宽计算；同一组公开报价的共同资格条件只写一次，差异条件保留报价或客群标识。

客群标签规则也用于备注中的报价前缀，避免只含 Personal 的组在备注里重复出现 Personal。单一 Premier/Preferred 等专属类别不逐条贴标签，但必要资格仍在备注中写一次。该显示规则不改变 Personal 最高值筛选，也不改变处理报告中记录的真实客群。

程序保留原业务表名称和参考顺序；删除的是有明确命名模式的采集明细。出现未知业务表或缺少参考业务表时停止，不擅自删除。它直接编辑 OOXML 中必要的部分，保留未涉及的文件部件，避免普通读写库丢失 Excel 扩展格式。

## 必须查看的处理报告

- `sgd_winners`：每家银行/期限所选客户类别、利率、实际期限和来源行。
- `comparison_mode` / `comparison_columns`：记录 `latest_two_columns` 口径，以及各表、各区块实际使用的列号、原表头行和日期。`previous` 固定为空，不再指向外部工作簿；只有相邻日期统一时才填写便于查看的 `previous_date`。
- `historical_consolidations`：记录同银行历史行的原始值、资格判定和合并结果。现行完整公开报价模式从可判定为普通个人的历史行合并；无法确认资格的历史值在审计中保留。相邻比较列标为「原表最高值」。
- `historical_text_rates`：旧历史日期列里的“2.2%（电子银行）”等组合文字转成数值时，保留原文与选取结果；金额或报价说明专用列不作为日期利率列处理。
- `legacy_errors`：原有 `#REF!` 等错误在成品显示 `-`，原错误及公式记在这里，不冒充零利率。
- `missing_previous`：当前有报价，但输入表相邻比较列没有有效数字的记录。
- `retained_amount_conflicts`：不能安全合并的金额行。
- `source_note_issues`：原备注明显混入其他银行条款、或过长无法可靠摘要时，成品显示资格待核，原文保留在报告。程序不会把这种文本当成已确认的客户资格。
- `summary_rate_corrections`：其他汇总区块与对应主表最高值的调整记录；原来误写在利率格里的说明移到备注。

处理报告明确记录这些限制。格式整理不等于重新核验银行网页，也不自动将待复核数据标为人工通过。

## 接入自动化框架

```python
import json
from pathlib import Path
from market_rates.report_format import format_report

report = format_report(
    input_path=collected_report,       # 本期完整调研，仍含采集明细
    template_path=format_reference,   # 用户维护的格式基准
    output_path=final_report,          # 新路径，不覆盖
)
Path(audit_path).write_text(
    json.dumps(report, ensure_ascii=False, indent=2, default=str),
    encoding="utf-8",
)
```

API 返回处理报告字典。输入/模板哈希不变、写出回读、汇总与主表规则、每个增幅的缓存结果等检查完成后才发布输出。失败时抛异常；命令行返回非零退出码。`dry_run=True` 执行完整内存预检查，不写 XLSX。

一键采集在完整调研生成后调用本步骤，并与彩虹格式整理一起交付四份工作簿。正式交付按明细引用定位全量调研中的获选产品行，即使最高值位于同银行区块的第二个产品行。格式对齐版按银行及期限展示对应最高值。关联记录见 `quote-coverage.audit.json`，四份文件均含「全部公开报价」与「Personal最高值」。运行和交付见 [一键运行说明](../一键运行说明.md)。
