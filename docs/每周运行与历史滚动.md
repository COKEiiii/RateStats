# 每周运行与历史滚动

初始底稿位于 `inputs`，未自动登记为本项目的已批准历史。人工确认后的新结果才进入本项目历史。

1. 双击 `一键运行.command` 采集官网，完成后检查四份交付工作簿及「查看运行记录.html」。
2. 检查新增/变化、异常及来源校验结果。文字模型通过检查也不代表自动批准。
3. 检查完成后，双击 `确认本期作为历史底稿.command`。默认读取最新 SGD 阶段输出。核对显示的目录后输入 `YES`，将两份核对过的工作簿登记到 `history/`。全量任务选用哪两份输入仍由「选择处理文件.command」的设置决定。

## 日期与历史

- 同一天再次运行：在新的输出文件中更新当前日期列，不重复插入相同日期。已确认文件仍单独保留。
- 日期晚于已确认版本：在 SGD 促销 C 列插入本期日期，原日期列整体右移。两期变动始终使用最新列减紧邻上一列。
- 每次使用独立命名的输入明细表。历史公式继续引用各自的旧明细，不会被本期输入覆盖。
- SGD 促销与外币促销、挂牌分别按已有模板规则更新；保留历史日期列和旧明细引用。
- 本期缺少可验证报价时显示 `-` 或来源状态。业务规则允许引用已截止的最新公告时，保留公告期限与参考标识。
- 历史列按实际运行日期滚动。启动频率由手动操作或外部调度决定。

## 人工修正

在本期输入明细表中修改利率或产品名，确认本期时会登记为可延续修正。下期只匹配同一银行、产品、实际期限、客群、渠道、金额档位和新资金条件；适用条件改变时不强行套用旧修正。产品没采集到或已过期时，旧修正也不能使其重新参与排名。

只修改其中一本工作簿的明细，可以在下一次生成时同步到两本；如果两本被改成不同值，确认程序会停止并指出冲突。当前两本的排序要通过重新生成完成。原始模型响应始终保留，不会被人工值覆盖。

生成的调研表 B 列产品说明若有人工备注，确认时与生成记录比较并登记；下次对应产品继续附带该备注。整行移动、改银行名称、期限或金额条件等结构修改，应先检查映射，不能当成普通利率修正。

## 当前展示规则

完整公开报价模式按实际期限展示，2M、4M、5M、8M、10M 等缺少的分组可扩展，8M 与 9M 独立。新增产品扩展原银行区块，同日重跑按产品匹配已有行。

各产品最新公告中的所有已核验报价完整保留，包括来源当期公布的 CIMB、HLF 和 HSBC 产品，以及 BOC 手机银行和 SmartSaver 柜台组合等独立产品。Personal 最高值仅从普通个人可参与的 personal／all 报价中选择；专属客群不作为替代。旧公告中消失的金额档不补入本期；已截止的最新公告明确标注有效期和参考属性。

本期 C 列只显示报价，不显示涨跌箭头。箭头保留在“当日最高报价变动”栏；原有历史条件格式保留。新增行与日期列生成后会检查条件格式的实际适用范围，避免复制行样式时把箭头带入报价栏。

`重新生成已验证表格.command` 只使用冻结批次，不重新访问银行。文件内保留各银行真实采集日期；不能把该入口当成下周最新行情采集。

## 出错后

检查页面和运行日志保存在当批输出及运行目录。中断后用「继续上次全量任务.command」搜索批次，查看启动时间、当前阶段和上次错误。符合现行续跑规则的批次从断点继续。历史底稿通过显式确认操作登记，详见 [一键运行说明](../一键运行说明.md#中断后继续)。
