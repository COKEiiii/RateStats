# 彩虹表格式整理程序

这是采集完成后的离线整理阶段。使用 Python 3.11 或以上版本，仅依赖标准库；正常运行不需要 Excel、网络、模型或第三方 Python 库。输入为采集程序生成的全量彩虹表，参考文件只提供样式，不提供报价或日期。

## 自己运行

在项目目录打开终端，指定已完成批次的全量彩虹表。将示例输入换成实际路径。

```sh
.venv/bin/python -m market_rates.rainbow_format \
  --input "outputs/批次目录/日期_全量_彩虹表.xlsx" \
  --template "templates/rainbow-format.xlsx" --output "outputs/example/rainbow.xlsx"
```

查看可用选项：

```sh
.venv/bin/python -X utf8 -m market_rates.rainbow_format --help
```

`--dry-run` 只解析、筛选和检查，不写文件。`--audit 路径.json` 可以指定检查报告路径，默认与输出同目录、同名 `.audit.json`。输出和检查报告均拒绝覆盖；再次运行请换一个输出文件名或新目录。

## 接入自动化框架

```python
from market_rates.rainbow_format import format_rainbow

audit = format_rainbow(
    input_path=collected_rainbow_path,
    template_path=rainbow_template_path,
    output_path=finished_rainbow_path,
)
assert audit['validation']['passed']
```

函数成功返回检查报告字典；数据不完整、原始引用缺少缓存、未知布局或路径冲突会抛出异常，命令行返回非零退出码。整理不会重采集银行报价。应把这一阶段接在采集与核验之后，把输出路径交给后续分发流程。

## 处理口径

- 独立格式整理输出 `SGD Promotional Rate`、`SGD Board Rate`、`USD Rate + Other Currency Rates` 三张业务表。利率写为数字，清理收集辅助表和外部引用。正式交付另附两张统一报价审计页。
- 促销和挂牌均保留各产品、客群、渠道、金额档及条件；相同利率但不同产品或条件不合并。每银行、期限形成连续块，按最高合资格 Personal 利率排序，块内先显示该获选记录，再保留全部其他报价。无 Personal 时保留专属报价并排在末尾。
- Personal 包括 `personal` 和普通个人可参与的 `all`，包含新资金要求；Premier、Preferred、Private、Corporate 等专属客群不参与最高值。并列最高时选较低的可比起存金额，再按稳定已核验输入行顺序选择；金额币种不可比时直接采用稳定顺序。金额、渠道、条件来自同一条获选记录，全部并列报价保留。
- 按实际期限分组，8M 与 9M 分开。模板没有的期限动态增加；CNY 及其他外币挂牌除最高值概览外，增加逐条公开报价区。
- 外币综合矩阵继续采用促销优先、没有促销时取挂牌。人民币保留 CNH 的原金额币种。矩阵每银行一行，只有整行没有有效报价才删除；零利率保留。
- SGD Condition 保留金额、Personal／Premier／Preferred 等客群和已知渠道；其他 Amount 仅保留金额。必要资格、渠道、实际期限、公告截止信息写在利率单元格批注中，完整原文保留在检查报告。
- 复用参考表期限配色、字号、边框和列宽，BOC 保留红色文字。各期限独立排序、压缩行；SGD 挂牌排序单位是银行块。行高从参考表基准开始，按完整金额和 Condition 的实际长度增长，避免遮挡。
- 参考表的 FTP 手工基准、BEFORE、临时重复报价与辅助工作表不复制。日期取输入业务表一致的采集日期。AUD/EUR/GBP/NZD 的源表额外促销期限块保留。

## 输入契约与检查

当前支持全量采集彩虹表的三张业务表、对应明细表和参考文件的既有布局。业务表 A1 必须包含一致的 `YYYY-MM-DD` 日期；SGD 标题第 2 行；外币区块按标题识别。明细表名含本批日期。输入中的利率引用必须有已保存的数值缓存；原本为数字的报价必须能与本批明细核对。未来采集格式结构性变化时，应更新解析器，程序不会静默输出部分数据。

检查报告记录输入哈希、全部候选、逐条保留报价及来源行、并列处理、缺失行和数据问题；不再删除低于最高值的 Personal 报价。银行块记录全客群最高值及 Personal 排序值，并检查报价和条件一致。格式整理阶段检查三张业务表无公式、外链及错误值；四份正式交付再统一附加“全部公开报价”“Personal最高值”两张审计表及覆盖记录。源文件混入其他银行条款时标记资格待核；已截止的最新公告保留截止提示。

运行回归检查：

```sh
.venv/bin/python -m unittest tests.test_rainbow_format tests.test_report_format
```

独立整理的写出检查由 Python 执行。全量交付还会用桌面 Excel 检查四份文件能否原生打开。正式交付与邮件入口见 [一键运行说明](../一键运行说明.md)。

## 产品变化的适应范围

两套转换器都是采集后的整理步骤。上游需要重新生成完整本期输入，业务表、汇总表和明细必须来自同一批数据，引用和缓存一致。

| 变化 | 支持情况 |
| --- | --- |
| 已支持币种、展示期限中增加或减少产品、金额档、银行行 | 依本期行数重选报价和调整布局，不要求与样板银行数量一致。 |
| 删除最高报价，尚有其他合资格报价 | 调研表重选 Personal 最高值；SGD 促销彩虹表重选剩余 Personal 最高值及其条件，保留专属客群报价，并重新排序，无 Personal 时移到末尾。 |
| 新产品没有上期可比记录 | 调研表使用输入表最新两列，相邻列缺失时增幅显示 `-`，不补 0 或跨文件补写历史值。 |
| 彩虹表某个促销区块全部下架并从输入删除 | 支持已知币种的促销区块缺席；AUD/EUR/GBP/NZD 空促销块不输出。主业务表和挂牌/综合矩阵结构仍须存在。 |
| 截止日期已过，但产品仍在本期输入 | 两套转换器不会自行删除；保留原有“最新公开参考、公告已截止”的提示。到期删除由上游采集/有效性规则决定。 |
| 只改明细，业务表或汇总表没有更新 | 不属于完整输入，不保证同步；应先由采集框架重建全量文件。 |
| 新币种、新展示期限、改表名/列结构、缺来源或公式缓存 | 需要补充结构映射或修复输入；会明确报错，不能宣称任意格式都能自适应。 |
